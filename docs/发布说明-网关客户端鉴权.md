# 发布说明 — 网关客户端鉴权（feat/gateway-client-auth）

> 发布日期：2026-09-07
> 设计依据：[2026-09-07-gateway-client-auth-design.md](superpowers/specs/2026-09-07-gateway-client-auth-design.md)（含 §9 评审裁决）
> 实施计划：[2026-09-07-gateway-client-auth.md](superpowers/plans/2026-09-07-gateway-client-auth.md)
> 配套操作文档：[tls-setup.md](nginx/tls-setup.md)、[测试指南.md](nginx/测试指南.md)、[llm-routing.example.conf](nginx/llm-routing.example.conf)

本分支为数据面（`/v1*`）引入三层鉴权纵深：nginx 凭据白名单 + TLS/限流 → 网关 `verify_client`（`GATEWAY_CLIENT_API_KEY`）→ 引擎原生 `--api-key`。客户端 key 只用于准入，验完即丢，上游认证仍用各 profile 的 `api_key`。**包含三项破坏性变更，切换必须走本文 runbook。**

## 1. 三条破坏性变更

1. **`/v1*` 全部端点强制 `GATEWAY_CLIENT_API_KEY`，未配置则全部 401**。网关 fail-closed：`.env` 未配置该键时，所有 `/v1*` 请求返回 401（`not configured`），属预期行为而非故障。上线前必须在 C 机 `.env` 配好新 key（生成命令见 `.env.example` 注释：`python -c "import secrets;print('sk-'+secrets.token_urlsafe(32))"`）并重启网关。
2. **裸 `POST /v1` 连通性探测从 200 变 401**。该端点此前匿名返回 200 供客户端探测 baseUrl 可用性；现同样要求凭据。依赖 baseUrl 探测的客户端（hertz 等）需带 key，或改探 `GET /v1/models`（带 key）。
3. **nginx 5000 端口由 http 一刀切 https（不做 http/https 双监听）**。切换瞬间起，仍用 `http://<B机>:5000/...` 的客户端立即 TLS 握手失败，属预期。所有客户端 `base_url` 改 `https://`，并信任自建 CA 或显式关闭校验（`-k` / `verify=False`，属安全降级，见 [tls-setup.md](nginx/tls-setup.md) §3/§4 与迁移清单）。

## 2. 密钥策略

- 新 `GATEWAY_CLIENT_API_KEY` **必须另行生成**，**不得复用** `fly@@see`——该值已在历史 PowerShell 报错日志中明文泄露（spec §9 裁决 4）。生成命令见 `.env.example` 注释。
- 建议一并轮换管理面 `API_KEY`。注意它是各引擎 profile 中 `api_key: ${API_KEY}` 的插值源：改动后需**重启全部模型进程**并**重新登录 webui**，否则引擎侧与网关侧 key 不一致会导致上游 401。
- 密钥明文严禁写入审计日志/入库；`modelctl nginx-snippet` 产物含明文凭据 map，上传 B 机后 `chmod 600`，严禁提交入库。

## 3. 切换 runbook（线性步骤，一次窗口内完成）

按顺序执行，任一步失败即停止并排错，勿跳步：

1. **配置新 key**：C 机 `.env` 设置 `GATEWAY_CLIENT_API_KEY`（用上文命令新生成；如决定一并轮换 `API_KEY`，在此步同时完成）。
2. **重启网关并确认**：`modelctl gateway restart`（等价：`modelctl gateway stop; modelctl gateway start`）。随后 `modelctl gateway status` 确认，期望输出"运行中，/v1/models 正常"（该命令会用 `GATEWAY_CLIENT_API_KEY` 探测 `/v1/models`；若提示"未配置 GATEWAY_CLIENT_API_KEY"则回到第 1 步）。
3. **重新生成 nginx 片段并上传**：`modelctl nginx-snippet --node <节点ID> --host <节点IP>`（自动读 `.env` 的 `GATEWAY_CLIENT_API_KEY` 生成含凭据 map 的路由片段）。产物上传 B 机 `/etc/nginx/conf.d/` 并 `chmod 600`（conf.d 已被 nginx.conf 默认 include，无需改主配置）。
4. **部署 TLS**：按 [tls-setup.md](nginx/tls-setup.md) §2 生成/部署自建 CA 与服务端证书，server 块 `listen 5000 ssl`；`nginx -t && systemctl reload nginx`。
5. **客户端迁移**：按 [tls-setup.md](nginx/tls-setup.md) §4 迁移清单逐端把 `base_url` 改 `https://`、按路径配对应凭据（网关路径带 `GATEWAY_CLIENT_API_KEY`，直连路径带该模型 profile `api_key`，分工见 [测试指南.md](nginx/测试指南.md) §3.1）。
6. **回归验证**：按 [测试指南.md](nginx/测试指南.md) §3.1 curl 矩阵全量回归，重点覆盖 401（缺凭据/错 key，用例 ⑨）与 429（`limit_req` 30r/m burst=60 连发触发）用例；另按 spec §4 验证 nginx 侧 `nginx -t` 通过且 reload 后无 5xx。

- **profile 未配置 `api_key` 时，网关会把客户端请求的 `Authorization` 透传给该引擎**（`gateway.py` 上游认证分支）。同信任域内属低危，后续票跟进。
