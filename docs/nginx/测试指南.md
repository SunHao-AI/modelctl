# 多模型路由 · 部署与测试指南

> 配套设计：[2026-08-19-multi-model-routing-design.md](../superpowers/specs/2026-08-19-multi-model-routing-design.md)
> nginx 参考配置：[docs/nginx/llm-routing.example.conf](llm-routing.example.conf)
> 适用场景：B 机 nginx 多模型路由 + C 机 modelctl 网关（model 参数路由）

## 0. 架构速览

```
A 设备（cc-switch / OpenAI SDK）
        │
        ▼
B 机 nginx :5000
        │
        ├── /210/llm/<模型>/v1/...         路径式直连 → C 机模型端口（如 18888）
        ├── /210/llm/<模型>/v1/api/usage   按模型用量 → C 机 :5002
        ├── /210/llm/v1/...                统一网关 → C 机 :5003（按 body.model 分发）
        └── /210/llm/v1/api/usage          旧用量（兼容旧卡片）→ C 机 :5002
```

模型注册表单一来源 = `models/*.yaml`；nginx map 片段由 `modelctl nginx-snippet` 生成。

> **模型名 = profile 的 `name` 或其 `alias`**。当前 llamacpp 模型已配置短名别名：
> `deepseek-v4-flash-llamacpp` ↔ `deepseek-v4-flash`、`qwen3.8-llamacpp` ↔ `qwen3.8`。
> URL 路径、网关 `model` 参数、用量 `?model=` 均可用长名或短名。

## 1. 部署服务器（C 机）配置

```bash
# ① 安装网关依赖（fastapi / uvicorn / httpx）
cd /path/to/modelctl && uv sync --extra dev --extra gateway

# ② .env 追加（参考 .env.example）
NODE_ID=210
NODE_HOST=192.168.77.210
GATEWAY_HOST=0.0.0.0
GATEWAY_PORT=5003
GATEWAY_DEFAULT_MODEL=deepseek-v4-flash
GATEWAY_READ_TIMEOUT=600

# ③ 确认模型已启动（deepseek-v4-flash-llamacpp → 18888）
modelctl status

# ④ 启动用量统计服务（用量路由依赖 5002）
modelctl stats start

# ⑤ 启动网关
modelctl gateway start
modelctl gateway status        # 期望：网关：运行中，/v1/models 正常

# ⑥ 本地验证网关（不经 nginx，直连 C 机）
curl -s http://127.0.0.1:5003/v1/models
curl -s http://127.0.0.1:5003/v1/chat/completions -H 'Content-Type: application/json' \
  -d '{"model":"deepseek-v4-flash","stream":false,"messages":[{"role":"user","content":"hi"}]}'

# ⑦ 生成 nginx map 片段（供 B 机使用；输出含 name 与 alias 两条目）
modelctl nginx-snippet --node 210 --host 192.168.77.210
```

注意事项：

- 防火墙需放行 `5003`（网关）、`5002`（统计）、模型端口（如 `18888`）给 B 机。
- 新增模型流程：新增一条 profile → `modelctl start <name>` → 重新执行 ⑦ 生成片段 → 更新 B 机 `/etc/nginx/llm-routes/`。

## 2. nginx 服务器（B 机）配置

```bash
# ① 创建路由目录
mkdir -p /etc/nginx/llm-routes/

# ② 在 C 机生成片段并上传（C 机执行 1-⑦）
modelctl nginx-snippet --node 210 --host 192.168.77.210 > llm-routes-210.conf
scp llm-routes-210.conf root@B机IP:/etc/nginx/llm-routes/
```

### 2.1 nginx.conf（http 块）

在 `include /etc/nginx/sites-enabled/*;` 之前加入：

```nginx
include /etc/nginx/llm-routes/*.conf;
```

### 2.2 sites-enabled/myflaskapp（server 块）

删除原两条规则：

```nginx
location ~ ^/210/llm/(.*)$ { ... }              # 旧 LLM 主流量 → 18888
location ~ ^/210/llm/v1/api/usage(.*)$ { ... }  # 旧用量 → 5002
```

替换为 4 条新 location（**顺序固定不可乱**，完整示例见 `docs/nginx/llm-routing.example.conf`）：

| 顺序 | 用途 | 正则 | 转发目标 |
|---|---|---|---|
| 1 | 旧用量（兼容旧卡片） | `^/(\d+)/llm/v1/api/usage(.*)$` | `:5002/api/usage$2` |
| 2 | 按模型用量 | `^/(?<node_id>\d+)/llm/(?<model_name>[^/]+)/v1/api/usage$` | `:5002/api/usage?model=$model_name` |
| 3 | 网关（model 参数） | `^/(?<node_id>\d+)/llm/(?<llm_rest>v1/.*)$` | `:5003/$llm_rest`（**保留 v1/ 前缀**） |
| 4 | 模型直连 | `^/(?<node_id>\d+)/llm/(?<model_name>[^/]+)/(?<llm_rest>.*)$` | map 注册表命中端口；未知 404 |

关键点：

- **location 3 必须捕获并保留 `v1/` 前缀**（`(?<llm_rest>v1/.*)`），否则转发到网关的路径缺少 `/v1`，网关返回 404。
- location 4 通过 `rewrite ^/\d+/llm/[^/]+/(.*)$ /$1 break;` 剥离 `/<node>/llm/<模型>` 前缀，保留 `/v1/...` 转发给模型。
- 网关与模型直连均需关闭缓冲保证 SSE 流式：`proxy_buffering off;`（网关另加 `proxy_cache off;`、`X-Accel-Buffering no`）。
- 通用代理头（Host / X-Real-IP / 超时）已在 nginx.conf http 块定义，location 内无需重复。

### 2.3 校验并重载

```bash
nginx -t && systemctl reload nginx
```

## 3. 客户端测试

### 3.1 curl 校验矩阵（`<B>` 替换为 B 机地址）

```bash
# ① 路径式直连-模型列表
curl -s http://<B>:5000/210/llm/deepseek-v4-flash/v1/models

# ② 路径式直连-对话
curl -s http://<B>:5000/210/llm/deepseek-v4-flash/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"deepseek-v4-flash","stream":false,"messages":[{"role":"user","content":"你好"}]}'

# ③ 网关-缺省 model（回退默认模型，旧卡片行为不变）
curl -s http://<B>:5000/210/llm/v1/chat/completions \
  -H 'Content-Type: application/json' -d '{"messages":[{"role":"user","content":"你好"}]}'

# ④ 网关-显式 model 切换
curl -s http://<B>:5000/210/llm/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"deepseek-v4-flash","messages":[{"role":"user","content":"你好"}]}'

# ⑤ SSE 流式（-N 逐块输出，验证 token 即时推送）
curl -N -s http://<B>:5000/210/llm/deepseek-v4-flash/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"deepseek-v4-flash","stream":true,"messages":[{"role":"user","content":"讲个笑话"}]}'

# ⑥ 旧用量（兼容旧卡片）
curl -s "http://<B>:5000/210/llm/v1/api/usage"

# ⑦ 按模型用量
curl -s "http://<B>:5000/210/llm/deepseek-v4-flash/v1/api/usage"

# ⑧ 未知模型路径 → 期望 404
curl -s -o /dev/null -w '%{http_code}\n' http://<B>:5000/210/llm/ghost-model/v1/models
```

预期结果：

| 用例 | 期望 |
|---|---|
| ①-④ | 200，正常 JSON（模型名被正确改写/回退） |
| ⑤ | 200，token 逐块输出（SSE） |
| ⑥⑦ | 200，cc-switch 兼容用量 JSON |
| ⑧ | 404 |

### 3.2 cc-switch（A 设备桌面端）

| 卡片 | baseUrl | 说明 |
|---|---|---|
| 直连（新） | `https://xxx:5000/210/llm/deepseek-v4-flash/v1` | 每模型一张卡 |
| 网关（旧，行为不变） | `https://xxx:5000/210/llm/v1` | 缺省/未知回退默认模型 |
| 用量查询 | `https://xxx:5000/210/llm/deepseek-v4-flash/v1/api/usage` | 粘贴到「用量查询 → 自定义」 |

### 3.3 OpenAI 兼容 SDK

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://xxx:5000/210/llm/v1",   # 网关；或直连 /210/llm/deepseek-v4-flash/v1
    api_key="root123456",                       # 与 .env 的 API_KEY 一致
)
resp = client.chat.completions.create(
    model="deepseek-v4-flash",
    messages=[{"role": "user", "content": "你好"}],
    stream=True,
)
for chunk in resp:
    print(chunk.choices[0].delta.content or "", end="", flush=True)
```

## 4. 排错速查

| 现象 | 排查方向 |
|---|---|
| ③④ 网关路径 502 | C 机网关未启动（`modelctl gateway status`）或依赖未装（`uv sync --extra gateway`） |
| ① 直连 502 / 超时 | 模型未启动（`modelctl status`）；防火墙未放行模型端口 |
| 网关路径 404 | B 机 location 3 未保留 `v1/` 前缀（需应用修复后的配置） |
| 未知模型名非 404 | location 4 的 `return 404` 缺失或被其他 location 抢占 |
| 用量无数据 / 显示错误 | C 机统计服务未启动（`modelctl stats start`）；或模型无 Prometheus 指标（ollama 不支持精确统计） |
| 新增模型后直连 404 | 未重新生成并上传 map 片段（`modelctl nginx-snippet` → B 机 `/etc/nginx/llm-routes/` → reload） |
| 流式不推送（一次性返回） | 网关/直连 location 缺 `proxy_buffering off;` |

## 5. 常用命令速查

```bash
# C 机
modelctl gateway start | stop | status     # 网关生命周期
modelctl stats start | stop                # 用量统计服务
modelctl nginx-snippet --node 210 --host 192.168.77.210   # 生成 map 片段
modelctl status                            # 模型实例状态

# B 机
nginx -t && systemctl reload nginx         # 校验并重载配置
```
